1.1 使用格式
class A<T> {}
interface B<T1,T2> {}

1.2 使用说明
1）我们在声明完自定义泛型类以后，可以在类的内部（比如：属性、方法、构造器中）
使用类的泛型。
2）我们在创建自定义泛型类的对象时，可以指明泛型参数类型。一旦指明，内部凡是使
用类的泛型参数的位置，都具体化为指定的类的泛型类型。
3）如果在创建自定义泛型类的对象时，没有指明泛型参数类型，那么泛型将被擦除，泛型
对应的类型均按照Object处理，但不等价于Object。
    ==> 经验：泛型要使用一路都用。要不用，一路都不要用。
4）泛型的指定中必须使用引用数据类型。不能使用基本数据类型，此时只能使用包装类替换。
5）除创建泛型类对象外，子类继承泛型类时、实现类实现泛型接口时，也可以确定泛型结构
中的泛型参数。比如：SubOrder2
如果我们在给泛型类提供子类时，子类也不确定泛型的类型，则可以继续使用泛型参数。比如：
SubOrder3
我们还可以在现有的父类的泛型参数的基础上，新增泛型参数。比如：SubOrder4，SubOrder5

1.3 注意点
1）泛型类可能有多个参数，此时应将多个参数一起放在尖括号内。比如：<E1,E2,E3>
2）JDK7.0 开始，泛型的简化操作：ArrayList<Fruit> fruitList = new ArrayList<>();
3）如果泛型结构是一个接口或抽象类，则不可创建泛型类的对象。
4）不能使用new E[]。但是可以：E[] elements = (E[])new Object[capacity];
    参考：ArrayList源码中声明：Object[] elementData，而非泛型参数类型数组。
5）在类/接口上声明的泛型，在本类或本接口中即代表某种类型，但不可以在静态方法中
使用类的泛型。
6）异常类不能是带泛型的。

2. 自定义泛型方法
2.1 问题：在泛型类的方法中，使用了类的泛型参数。那么此方法是泛型方法吗？

2.2 格式
权限修饰符 <T> 返回值类型 方法名(形参列表) {
    // 通常在形参列表和返回值类型的位置会出现泛型参数T
}

2.3 举例
public <E> E method(E e) {
    return null;
}
2.4 说明
> 声明泛型方法时，一定要添加泛型参数<T>
> 泛型参数在方法调用时，指明其具体类型
> 泛型方法可以根据需要声明成static
> 泛型方法所属的类是否是一个泛型类，都可以

面试官：为什么泛型类型在运行时虽然被擦除，但并不等同于Object类型？
我：泛型在Java中是通过类型擦除实现的。运行时，泛型信息会被擦除，所有泛型参数
类型都会被替换为Object。例如，Box<T>在运行时，会变成Box，T会变成Object。然
而，编译器在编译时会根据泛型参数类型进行严格的类型检查，确保代码中的类型安全。
这意味着，即使运行时的类型是Object，编译器仍然会根据泛型的声明来检查类型安全。
因此，泛型类型和Object类型在语义上是不同的。泛型类型具有明确的类型信息，用于
编译时的类型检查，而Object是一个通用的类型，不具有具体的类型信息。这就是为什
么泛型类型在运行时虽然被擦除，但并不等同于Object类型。
